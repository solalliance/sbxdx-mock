# SBxDX 初期運用モック

[モックを開く](https://solalliance.github.io/sbxdx-mock/)

パート4名＋管理者の初期運用です。管理者・パート・クライアントを上部で切り替えます。会社・人物・回収記録はサンプルです。

## 資料提出からタスク完了まで

1. クライアントが「資料を提出」の資料名ごとの専用枠へアップロード。
2. 枠のIDで資料の種類を識別し、受領・格納後に社内で内容確認。不備は理由付きで差し戻し、再提出を依頼。
3. タスクは最初から一覧に並び、資料・前工程待ちはグレー。必要資料の確認完了と前工程の条件が揃うと青色に点灯。
4. パート本人が青色のタスクを任意に選び、自分の名前で確保。確保済みは紫色で他の人は選択不可。
5. 確保した本人が結果を記録して完了。緑色の完了タスクは再選択不可。

事前に全タスクの担当を割り当てる操作は不要です。休暇・退職の際は管理者が未完了の確保を引き継げます。

定款・謄本・e-Tax情報・eLTAX情報・前期申告書・前々期申告書・届出資料の7枠を用意。新規顧客登録の共通8タスクを反映しています。決算・年末調整などのサービスは維持し、固有の詳細定義は追加資料待ちです。

見込み客登録、問い合わせ・面談・見積・契約・受注、失注・保留とフォロー配信、請求・一部/全額入金、入金後の連携、顧客別TaxSys入口は継続しています。

## モックの範囲

ファイルはブラウザ内に保存し、TaxSysへの格納後の状態をシミュレーションします。実TaxSys API・実メール・本番認証は未接続。1ファイル1MB・総添付2MBまでです。

同一ブラウザの複数タブではWeb Locksで同時確保を検査します。異なる端末・ブラウザ間の確保は、本番のサーバー/DB実装で保証します。

組織拡張版はGitの `5c62d6c`、担当割当版は `5e40346` に保持。開発側には旧HTML・編集元・buildの保管コピーもあります。

[以前の構成の画面付き説明書](https://solalliance.github.io/sbxdx-mock/manual.pdf) は旧版資料です。現在の自己選択画面とは異なります。

### 資料の内容確認・再提出
アップロード・格納後は「内容の確認待ち」。社内の顧客別資料欄でファイルを確認し、問題なければ確認完了、不備があれば理由必須で差し戻す。クライアントの資料提出画面に理由と再提出入口を表示する。再提出は再確認が必要で、過去の判定・提出履歴も保持する。確認完了した必要資料が揃ったときに社内タスクを点灯し、実務タスクの完了とは区別する。内容の自動判定やメール実送信は行わない。
